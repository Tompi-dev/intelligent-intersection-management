# Порядок разработки

1. Каждый участник использует личный аккаунт и узнаваемые имя и email автора коммитов.
2. Для содержательной работы сначала создаётся реальная задача YouTrack: исполнитель, ожидаемый результат, критерии приёмки, приоритет и срок.
3. Ветка содержит выданный YouTrack ID: `<TASK-ID>-short-description`.
4. Коммиты отражают связные завершённые изменения, например `<TASK-ID>: Add requirements and acceptance criteria`.
5. Создаётся Pull Request / Merge Request с ID задачи, описанием и результатами проверки. Обратная ссылка добавляется в YouTrack.
6. В командном проекте изменения до слияния проверяет другой участник. Для индивидуального проекта значимые изменения проверяет руководитель в согласованных контрольных точках.
7. `main` служит проверенной базовой версией. Защиту ветки и доступы следует настроить на выбранном хостинге.
8. Задача закрывается после выполнения критериев приёмки.
9. Документы и диаграммы фиксируются постепенно, вместе с кодом. Искусственные коммиты и фиктивные ревью не подтверждают прогресс.

## Перед сдачей

Предоставьте доступ руководителю, команде и комиссии; проверьте его из соответствующего аккаунта. На проверенной версии создайте тег `pre-defense-1`, затем для следующих этапов `pre-defense-2` и `final-pre-defense`. Уже поданные теги не переносите. Команды ниже выполняются только в реальном настроенном репозитории после проверки выбранного коммита:

```sh
git tag -a pre-defense-1 -m "First pre-defense submission"
git push origin pre-defense-1
```

Подготовьте сведения по шаблону `docs/submission.md`. На демонстрации проследите реальную задачу до ветки, коммита, запроса на слияние и замечаний ревью.
